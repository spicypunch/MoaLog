## 결론

2026-09-08 Stitch MCP 개선을 반영한 수정 화면은 **1차 개발의 구현 기준으로 사용할 수 있다.** 초기 검토에서 발견한 과소비 판정, 저축률 용어, 연소득 합계, 관리비 스키마·합계, 미확정 자동 연동 문제를 수정했다. P06 입력 변형, P07 1단계, 공통 바텀시트·확인창, 대표 빈값·오류 상태도 추가했다.

Stitch에는 초기 화면과 수정 화면이 함께 있으므로 개발 시 제목에 `(수정)`, `-A`, `-B`, `-S1`, `-S2`가 붙은 최신 화면을 우선 사용한다. 아래 P0·P1 내용은 최초 검토 근거로 남긴다.

## P0 · 개발 전에 반드시 수정

### 1. 과소비 규칙이 원본과 반대로 설명된다

영향 화면: P02, P11, P12, P20

원본 시트에서 과소비는 사용자가 직접 체크하는 값이다. 예산을 넘으면 자동 판정되는 기능이 아니다. 현재 P20은 카테고리 예산의 100%를 넘으면 과소비가 자동 점등된다고 설명하고, P02·P11에는 예산 대비 자동 감지처럼 읽히는 문구가 있다.

수정 기준:

- P12의 수동 과소비 토글을 유일한 판정 입력으로 사용한다.
- P02·P11은 `사용자가 과소비로 표시한 금액`이라고 설명한다.
- P20 Q3 답변은 `지출 입력에서 직접 과소비로 표시하면 월별 과소비 합계에 포함됩니다`로 교체한다.
- 자동 판정을 추가하고 싶다면 별도 신규 기능으로 정의하고 수동 표시와 구분한다.

### 2. 관리비 화면의 항목과 합계가 서로 맞지 않는다

영향 화면: P16, P17

P17의 화면 합계는 284,520원이지만 표시된 그룹 소계는 `121,640 + 135,500 + 32,000 - 1,520 = 287,620원`이다. 또한 원본 항목인 소독비와 선거관리위원회가 빠지고, 원본에 없는 공동수도료와 공동난방비가 들어갔다.

수정 기준:

- 관리비 항목을 기능 명세의 21개 항목과 정확히 일치시킨다.
- 모든 입력값, 그룹 소계, 화면 합계를 같은 예시 데이터에서 산출한다.
- P16 상세 합계와 P17 저장 전 합계가 동일해야 한다.
- 관리비차감은 음수 부호를 유지한다.

### 3. 연간 수입 합계가 한 화면 안에서 충돌한다

영향 화면: P02, P05

P05 상단은 2026년 수입 합계 78,000,000원을 표시하지만 월별 표의 연간 합계는 87,250,000원이다. P02도 78,000,000원을 표시한다. 어떤 값이 기준인지 개발자가 판단할 수 없다.

수정 기준:

- 월별 항목 합계와 상단 연간 합계를 동일한 데이터로 다시 계산한다.
- 디자인 예시를 유지하려면 월급 78,000,000원과 부수입을 분리해 `정기 수입`과 `전체 수입`으로 명확히 표시한다.
- 홈, 연간 표, 구성 분석에서 같은 연도의 같은 지표는 같은 값을 사용한다.

### 4. 저축률 이름이 계산 정의와 다르다

영향 화면: P02, P04

기능 명세에서 목적통장 포함 저축률은 50%, 순저축률은 38.5%다. P02는 50%를 `순 저축률`이라고 표시하고 P04는 38.5%를 `순저축(잉여)`라고 표현한다.

수정 기준:

- 50%는 `저축률 · 목적통장 포함`으로 표기한다.
- 38.5%는 `순저축률`로 표기한다.
- `잉여`는 수입-지출 잔액으로 오해될 수 있으므로 제거한다.
- 같은 지표 이름과 도움말을 모든 화면에서 통일한다.

### 5. 원본에 없는 자동 연동이 이미 동작하는 것처럼 표시된다

영향 화면: P04, P08, P09, P13, P14, P15, P17, P18

현재 디자인에는 계좌 자동이체 체크, 다음 달 자동 반영, 계좌·거래수단 자동 연계, 실시간 자산 집계, 계좌 연결, 파트너 실시간 연결, 클라우드 백업, 관리비의 고정지출 자동 반영이 들어 있다. 현재 기획에서는 구현 여부와 저장 방식이 정해지지 않았다.

수정 기준:

- P13 `실시간 집계`를 `직접 입력 기준` 또는 `입력값 합계`로 바꾼다.
- `계좌 연결` CTA는 `자산 항목 직접 추가`로 바꾼다.
- P14의 계좌번호·연동 정보 문구를 제거한다.
- P08·P09는 계획값을 자동 송금하거나 자동 반영한다고 설명하지 않는다.
- P15 자동 이체·거래 내역 연동 문구는 직접 입력 흐름으로 바꾼다.
- P17 저장 시 관리비 현황만 갱신하고, 고정지출 반영은 별도 확정 기능이 생길 때만 제공한다.
- P18의 실시간 동기화·파트너 알림·백업은 제품 범위 확정 전 숨긴다.

### 6. 목록에 보이는 정보를 지출 입력에서 만들 수 없다

영향 화면: P11, P12

P11 지출 목록에는 `아내 지출`, `남편 지출`, `공동 카드`, `공동 통장`이 표시된다. P12 입력 화면에는 지출자나 결제수단을 고르는 필드가 없다.

수정 기준은 둘 중 하나다.

- P11에서 지출자·결제수단 표시를 제거한다.
- 또는 P12와 데이터 명세에 `지출자: 공동/수아/종민`, `결제수단` 필드를 추가한다.

원본 현행 지출 상세에는 이 두 필드가 없으므로, 1차 이관 범위에서는 제거하는 쪽이 더 단순하다.

## P1 · 구현 기준 디자인으로 확정하기 전에 보완

### 7. 필요한 화면 상태와 입력 변형이 생성되지 않았다

P01~P20 기본 화면은 모두 생성됐다. 그러나 화면 설계서가 요구한 다음 변형은 별도 확인 가능한 디자인이 없다.

- P03 고정지출·저축투자 탭과 음수 항목 상태
- P04 고정지출·변동지출·저축투자 탭
- P06 고정지출 폼, 저축 폼, 음수 입력, 저장 오류
- P07 1단계 대상 월 선택
- P10 수아·종민 그룹, 빈 그룹, 중복 충돌 상태
- P11 빈 목록, 필터 결과 없음, 귀속 월과 실제 월 불일치 행
- P12 수정·삭제 상태와 필수값 오류
- P13 자산 없음과 미래 예상 상태
- P15 일부 미입력·0원 상태
- P16 월별 비교 탭
- P19 다른 관리 대상 탭과 순서 변경 모드
- B01~B09 바텀시트, D01~D04 확인창

개발자는 기본 화면 한 장만 보고 오류·빈값·편집 상태를 추측하게 된다. 최소한 P06, P07 1단계, P12 오류/수정, P17 부분 입력, B01~B09는 추가 디자인이 필요하다.

### 8. 월급 배분과 고정비에 자동이체 날짜가 추가됐다

영향 화면: P04, P08, P10

원본에는 월급 입금 예정일이나 고정비 자동이체일이 데이터 필드로 존재하지 않는다. 현재 화면은 `매월 25일`, `매월 1일`, `자동이체 전날 알림`까지 표현한다.

수정 기준:

- 1차 버전에서는 해당 날짜와 알림 문구를 제거한다.
- 유지하려면 항목 입력 폼, 반복 규칙, 알림 설정, 권한, 예외 월 처리까지 별도 명세한다.

### 9. 기준 연도가 섞여 있다

영향 화면: P10 및 나머지 2026년 화면

대부분 2026년 5월을 사용하지만 P10 고정비 점검은 `2025.05 기준`이다. `2026년 5월`로 통일하거나, 고정비 점검이 연도와 무관한 템플릿이면 날짜를 `월 기준 금액`으로 바꾼다.

### 10. 구버전 또는 신규 기능이 확정 기능처럼 섞였다

영향 화면: P02, P03, P04, P15, P18, P20

부부별 목표 기여율, 카테고리 예산 소진률, 자동 과소비 감지, 목적통장 목표 달성률, 엑셀/CSV 내보내기, 1:1 문의, 가계부 팁은 원본 현행 기능과 화면 명세의 기본 범위를 넘어선다.

수정 기준:

- 이번 이관에 필요한 기능은 남긴다.
- 있으면 좋은 기능은 `향후 기능`으로 분리하고 1차 개발 화면에서 숨긴다.
- 특히 P02 홈은 확정되지 않은 분석 지표를 빼고 목표·수입·지출·저축·수동 과소비에 집중한다.

### 11. 용어와 메뉴 이름을 통일해야 한다

영향 화면: P01, P04, P13, P18, P20

- P01의 `마이페이지`는 실제 메뉴인 `더보기` 또는 `가계부 기본 설정`으로 교체한다.
- `현재 모은 돈`, `연간 저축`, `목적포함 저축`, `순저축(잉여)`를 계산 명세에 맞는 두 용어로 통일한다.
- `확정 전환 시 예산 잔여액에 즉시 반영`은 현재 계산 정의에 없는 동작이므로 제거하거나 정의한다.
- 구성원 표시는 `남편/아내`, `수아/종민`, `개인(수아)` 중 한 체계로 통일한다. 예시는 사용자 이름을 우선한다.

## P2 · 시각 및 접근성 보완

### 12. 아이콘 버튼의 터치 영역과 접근성 이름

디자인 시스템은 48px 터치 영역을 정의하지만 실제 HTML에는 `p-1` 수준의 수정·더보기·이전 버튼이 있다. 아이콘만 있는 모든 버튼은 시각 영역과 별개로 48×48px 터치 영역을 확보하고 `목표 수정`, `이전 달`, `지출 필터`처럼 접근성 이름을 붙여야 한다.

### 13. 입력 필드의 프로그램 연결 레이블

P01, P06, P12, P17은 화면상 제목이 있지만 일부 입력에 `label-for`, `aria-label`, `aria-describedby` 연결이 확인되지 않는다. 표시 텍스트를 접근성 레이블로 연결하고, 필수·오류·도움말을 화면 읽기 프로그램이 함께 읽게 해야 한다.

P17의 반복 금액 필드는 단순히 `금액 입력`으로 읽히면 구분할 수 없다. `청소비 금액, 원`, `관리비 차감 금액, 원`처럼 항목명과 단위를 포함한 접근성 이름이 필요하다.

### 14. 차트만으로 정보를 전달하지 않기

P03, P13, P14는 차트 아래에 금액 목록과 범례가 있어 방향은 좋다. 구현에서도 목록을 유지하고 차트의 기간·전체 합계·각 항목 값에 접근성 설명을 제공한다. 예상 점선은 `예상` 텍스트와 함께 사용한다.

### 15. 긴 화면의 위치 인지와 고정 요소

P16, P17, P20은 스크롤이 매우 길다. P17은 그룹 접기, 입력 완료 수, 오류가 있는 첫 항목 이동을 제공하고 고정 저장 버튼이 마지막 입력을 가리지 않게 하단 여백을 확보한다. P20은 검색보다 목차 또는 질문 바로가기가 실용적이다.

### 16. 가로 스크롤 표의 모바일·접근성 대안

P05는 가로 표가 필요하지만 키보드·스크린리더 사용자는 현재 월과 항목 관계를 잃기 쉽다. 고정된 항목 열과 월 헤더를 유지하고, `월별 카드 보기` 또는 한 달씩 이동하는 대체 보기를 제공하는 것이 안전하다.

### 17. 작은 상태 배지의 명암 대비

현재 디자인 토큰의 11px 배지를 기준으로 과소비 빨강과 연한 배경은 약 4.02:1, 성장 초록과 연한 배경은 약 4.19:1로 작은 일반 텍스트 권장 대비 4.5:1에 미치지 못한다. 보조 회색과 아이보리 배경도 약 4.41:1이다. 글자색을 더 어둡게 조정하거나 배지 글자 크기와 굵기를 올려야 한다.

저장 성공·실패, 필터 결과 변경, P07 적용 개수, P17 자동 합계 변화는 시각적 토스트만 띄우지 말고 플랫폼 접근성 알림으로 전달한다.
